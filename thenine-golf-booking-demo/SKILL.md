# 더나인GC 골프예약 시연 스킬

## Overview

이 스킬은 Agentree/Hermes 시연에서 **더나인 골프클럽(더나인GC) 골프 예약 과정을 실제 브라우저로 보여주는 데모**를 준비하고 실행할 때 사용한다.

핵심 목표는 단순한 텍스트 보고가 아니라, 관객이 볼 수 있는 실제 브라우저에서 사람이 예약을 진행하는 것처럼 검색 → 공식 사이트 진입 → 팝업 정리 → BOOKING 이동 → 로그인/예약 가능 구간까지 빠르고 자연스럽게 보여주는 것이다.

단, 실제 예약 확정/결제/최종 제출은 대표님의 명시 승인 전에는 진행하지 않는다.

## When to Use

사용 조건:
- 대표님이 “더나인 골프예약 시연”, “더나인GC 예약 데모”, “골프 예약 브라우저 시연”을 언급할 때
- 더나인GC 예약 플로우를 반복 연습하거나 개선할 때
- 시연 중 브라우저 조작 속도, 팝업 정리, 로그인 지점, 예약 확정 안전선을 다뤄야 할 때
- 나중에 실제 시연 전까지 더나인GC 관련 업데이트를 누적해야 할 때

관련 일반 원칙은 `web-booking-automation` 스킬을 함께 따른다.

## Demo Target

- 골프장명: 더나인 골프클럽 / 더나인GC
- 공식 사이트: `https://theninegc.co.kr/`
- 검색 우선 채널: Naver 검색 권장
- Google 검색은 봇 감지/차단이 뜰 수 있으므로, 한국 로컬 골프장 시연에서는 Naver를 우선 사용한다.

## Default Demo Scenario

기본 시나리오가 별도로 지정되지 않으면 다음을 기준으로 한다.

- 대상: 더나인GC 골프 예약
- 인원: 3명
- 라운드: 18홀
- 시간대: 오전 06:00–08:00
- 날짜: 시연일 기준 다음 주 중 가능한 날짜
- 목표: 실제 예약 확정 전 단계까지 보여주기

날짜, 인원, 시간대가 대표님 지시와 다르면 대표님 지시를 우선한다.

## Demo Runbook

시연 흐름은 두 가지 버전으로 준비한다.

### A. 전체 시연형: 검색부터 보여주기

1. Naver에서 `더나인 골프클럽`을 검색한다.
2. 장소 카드에서 더나인 골프클럽이 맞는지 확인한다.
3. 주소/전화번호/홈페이지/예약 카드가 보이는 장면을 짧게 보여준다.
4. 공식 홈페이지 `theninegc.co.kr`로 이동한다.
5. 팝업을 빠르게 닫고 `BOOKING`으로 이동한다.

### B. 실전 속도형: 공식 사이트로 바로 진입

1. 주소창에 `https://theninegc.co.kr/`를 직접 입력한다.
2. 팝업을 빠르게 닫는다.
3. `BOOKING`으로 이동한다.
4. 로그인/예약 가능 단계까지 진행한다.

반복 시연이나 강의 시간이 짧을 때는 B를 우선한다. Naver 검색 장면이 필요할 때만 A를 사용한다.

## Visible Browser Demo Style

대표님은 텍스트 설명만이 아니라 **대표님/관객이 보는 모니터에 실제 Chrome 창이 열리고 조작되는 모습**을 원하신다. Hermes 내부/원격 브라우저 세션만 사용하면 대표님 모니터에 보이지 않으므로, 시연 요청 시 우선 로컬 Chrome을 새 창으로 연다.

Windows에서 로컬 Chrome 실행 예시:

```bash
'/c/Program Files/Google/Chrome/Application/chrome.exe' --new-window 'https://search.naver.com/search.naver?query=%EB%8D%94%EB%82%98%EC%9D%B8%20%EA%B3%A8%ED%94%84%ED%81%B4%EB%9F%BD'
```

로컬 Chrome 시연 전 필수 확인:
- Chrome 프로세스 실행 여부만 확인하고 끝내지 말고, **실제 화면 캡처에서 Chrome 창이 watched monitor에 보이는지** 확인한다.
- Telegram/Slack 등 메시지 앱이 전면을 빼앗거나 Chrome을 가릴 수 있으므로, 실제 조작 구간에서는 메시지 앱을 최소화한다.
- 듀얼 모니터 환경에서는 Chrome이 왼쪽/외부 모니터의 음수 좌표에 있을 수 있다. 화면에 안 보이면 창 좌표를 확인해 watched monitor 안쪽으로 이동한 뒤 진행한다.
- 사용자가 “멈춰 있어”, “안 보여”, “stop”이라고 하면 더 클릭하지 말고 즉시 현재 화면을 안정화하고 대기한다.

자세한 로컬 화면 제어/복구 절차는 `references/2026-06-09-local-chrome-visible-control.md`와 `references/2026-06-09-visible-chrome-dual-monitor-lesson.md`를 참고한다.

시연 방식:
1. 먼저 브라우저를 열어 화면에 Naver 검색 또는 공식 사이트 진입 장면이 보이게 한다.
2. 검색창에서 “더나인 골프클럽” 또는 “더나인GC”를 검색한다.
3. Naver 검색 결과에서 장소 카드/공식 홈페이지를 짧게 보여주고, 더나인GC가 맞는지 화면상 확인한다.
4. 공식 사이트 진입 후 “공지 팝업을 빠르게 정리하겠습니다”처럼 짧게 말하고 팝업/공지창을 빠르게 닫는다.
5. 상단 또는 메인 메뉴의 `BOOKING`을 클릭한다.
6. 로그인 페이지 또는 예약 가능 페이지까지 이동한다.
7. 로그인/예약 확정/결제/최종 제출 단계에서는 멈추고 상태를 명확히 보고한다.
8. 시연 후에는 “텍스트 요약 먼저”가 아니라 브라우저 시연형으로 바로 진행한다는 운영 기준을 따른다.

## Speed Profile

대표님 피드백: 기존 4배속도 너무 느렸다. 또한 예약 중간에는 설명 때문에 느려지는 것도 원치 않으신다. 안전 경계와 결과 보고를 제외하고는 장황하게 설명하지 말고 바로 실행한다.

더나인GC 시연/실행 기본 속도:
- 안전한 탐색/검색/팝업 닫기: **8배속 이상 실전 속도**
- 날짜 변경: 홈/BOOKING부터 다시 들어가지 말고, 현재 예약 화면에서 `Date_Click(yyyy, mm, dd)`로 날짜만 바꾼다.
- 설명: 진행 중에는 최소화한다. “확인했습니다/진행합니다” 수준으로 짧게 말하고, 결과와 최종 승인 질문만 명확히 한다.
- 마우스 이동: 중요한 전환에서만 보이게, 불필요한 긴 이동 제거
- 클릭 전/후 대기: 최소화
- 타이핑: 사람이 빠르게 입력하는 수준
- 단, 예약 확정/결제/최종 제출/취소 확정 앞에서는 확실히 멈춤

2026-06-09 재점검 결과:
- 공식 사이트 직접 진입 후 로그인 페이지까지는 네트워크 로딩 자체가 약 1초 내외로 빠르다.
- 체감 속도 병목은 사이트 로딩이 아니라 **5개 팝업을 하나씩 닫는 장면**이다.
- 팝업 정리 장면을 보여줄 필요가 없으면, 시연 전 `오늘 하루 동안 보이지 않기`로 팝업을 숨겨두는 것이 가장 빠르다.
- 팝업 정리도 시연해야 한다면, 해설을 길게 하지 말고 “공지 팝업을 빠르게 정리하겠습니다” 한 문장만 말한 뒤 `× CLOSE`를 연속 클릭한다.
- 팝업 본문을 잘못 클릭하면 공지사항 상세 페이지로 이동하므로 속도를 올리더라도 클릭 타겟은 `× CLOSE`로 정확히 잡는다.

목표 느낌:
> 관객이 AI가 실제로 조작하는 것은 알 수 있지만, 답답하지 않은 실전 속도.

## Known Site Flow

2026-06-09 재점검 결과 기준 관찰된 흐름:

1. Naver 검색 `더나인 골프클럽` 결과에서 장소 카드가 바로 노출된다.
   - 주소: 전북 김제시 금구면 대화1길 8-75
   - 전화번호: 063-548-3650
   - 홈페이지: `http://theninegc.co.kr/`
   - Naver 장소 카드 안에도 `예약` 영역이 보일 수 있다.
   - Naver 예약 카드의 일부 티타임은 `4인 필수`, `9홀X2회`, 제공자 `티스캐너`로 표시될 수 있으므로, 기본 시나리오가 3명일 때는 그대로 예약 진행하지 말고 조건 불일치를 확인한다.
2. `https://theninegc.co.kr/` 공식 홈페이지 접근 가능.
3. 초기 진입 시 여러 공지 팝업이 나타날 수 있다. 2026-06-09 기준 반복 실행에서 5개 팝업이 확인되었으며, 제목은 시즌/운영 공지에 따라 달라진다.
   - 확인된 예시: 제2퍼팅연습장 이용 안내, 6월 이용요금, 그린통기, 야간무인자판기오픈, 카트비면제
   - 이전 실행에서는 야간라이트 LED 교체 완료, 6월 주중 이벤트류 공지도 보였다.
   - 따라서 데모 중에는 팝업 제목을 고정 암기하지 말고, 보이는 팝업을 빠르게 닫는 절차를 우선한다.
4. 각 팝업 하단에는 `오늘 하루 동안 보이지 않기`와 `× CLOSE`가 있다.
5. 팝업의 큰 이미지/본문 영역은 공지 상세 페이지 링크이므로 잘못 클릭하면 공지사항 상세 페이지로 이동한다. 반드시 하단 오른쪽 `× CLOSE` 또는 하단 왼쪽 `오늘 하루 동안 보이지 않기`만 클릭한다.
6. 시연 당일 반복 연습/본 시연 전에는 `오늘 하루 동안 보이지 않기`를 사용해 팝업을 미리 숨기면 흐름이 빨라진다. 단, 팝업 처리 자체를 보여주는 시연이라면 `× CLOSE`를 빠르게 클릭한다.
7. 팝업을 닫은 뒤 상단 메뉴 `BOOKING`을 클릭하면 회원 로그인 페이지로 이동한다.
8. 로그인 리다이렉트 URL은 `https://theninegc.co.kr/html/member/login.asp?gopath=/html/booking/booking01.asp` 형태다.
9. 로그인 페이지에는 일반적으로 다음 요소가 있다.
   - 숨은 이동 경로: `/html/booking/booking01.asp`
   - 아이디 입력: `loginId`, name `memb_inet_no`
   - 비밀번호 입력: `loginPw`, name `memb_inet_pass`
   - 아이디 저장 체크박스: `idSave`
   - 로그인 버튼
   - 회원가입
   - 아이디/비밀번호 찾기
   - 홈 바로가기
10. 실제 티타임/예약 가능 여부는 로그인 후 확인해야 할 수 있다.

## Login Checkpoint

더나인GC 예약 가능 시간 확인은 회원 로그인이 필요할 수 있다.

로그인 화면에 도달하면:
- “현재 로그인 단계입니다.”라고 명확히 말한다.
- 아이디/비밀번호를 채팅에 요구하지 않는 것을 우선한다.
- 가능하면 대표님이 직접 브라우저에 입력하게 한다.
- 대표님이 명시적으로 대리 입력을 요청한 경우에만 입력한다.
- 비밀번호/인증정보는 기억, 파일, 스킬, 로그에 저장하지 않는다.

## Reservation Safety Boundary

예약 플로우의 핵심 안전선은 **예약하기 버튼을 누르기 직전에 대표님께 예약현황을 먼저 보여주고, 명시 승인을 받은 뒤에만 예약 확정하는 것**이다.

### Final Confirmation Protocol

`예약하기`, `예약 확정`, `결제`, `최종 제출`처럼 실제 예약을 생성하거나 되돌리기 어려운 버튼 앞에서는 반드시 다음 순서를 따른다.

1. **버튼을 누르지 않고 멈춘다.**
2. 현재 화면의 예약현황을 확인한다.
3. 대표님께 예약현황을 요약해서 보여준다.
4. 마지막에 명확히 질문한다: **“이 예약현황으로 예약하기 버튼 눌러도 될까요?”**
5. 대표님이 “응”, “진행해”, “예약해”, “눌러”, “확정해도 돼”처럼 명시 승인한 경우에만 예약하기 버튼을 누른다.
6. 승인 전에는 절대 예약하기/결제/최종 제출 버튼을 누르지 않는다.

대표님께 보여줄 예약현황에는 가능한 한 다음 항목을 포함한다.

- 골프장: 더나인GC / 더나인 골프클럽
- 날짜
- 티오프 시간
- 코스/홀 정보: 18홀 등
- 인원: 예) 3명
- 요금/그린피/카트비/캐디피 등 화면에 보이는 비용
- 취소/위약 규정 또는 주의사항
- 예약자명/연락처 등 화면에 보이는 예약자 정보
- 아직 불확실하거나 화면에서 확인되지 않은 항목

최종 확인 문장 예시:

> 대표님, 현재 예약현황은 더나인GC / 2026-XX-XX / XX:XX 티오프 / 3명 / 18홀 / 표시 요금 XX원입니다. 취소 규정은 화면상 XX로 보입니다. 이 예약현황으로 **예약하기 버튼 눌러도 될까요?**

### Hard Stop Actions

다음 버튼/행동 앞에서는 반드시 위 Final Confirmation Protocol을 수행한다.

- 예약하기
- 예약 확정
- 결제
- 최종 제출
- 취소 확정
- 약관 동의 후 되돌리기 어려운 제출
- 회원정보 변경

대표님이 “예약했어?”라고 물으면 상태를 먼저 짧고 명확히 답한다.

예시:
- “아니요, 아직 예약하지 않았습니다. 예약하기 버튼 직전에서 예약현황 확인 단계입니다.”
- “아니요, 결제나 최종 예약 확정은 누르지 않았습니다.”
- “네, 대표님이 예약현황 확인 후 승인하셔서 확정했습니다.”

## Demo Narration Template

시연 중 짧게 말할 문장:

## Fast CDP Automation Mode

반복 시연이나 실제 업무 자동화에서는 느린 마우스 애니메이션 대신 `scripts/thenine-fast-booking.mjs`의 Playwright/CDP 모드를 사용한다.

실행 위치:

```bash
cd thenine-golf-booking-demo/scripts
npm install
npm run doctor
npm run cdp-start
npm run cdp-doctor
npm run cdp-show -- --date YYYY-MM-DD --holes 18 --prefer cheapest-latest --step-ms 700
# 당일 최저가 대비 N원 이내 후보 중 가장 늦은 시간 선택:
npm run cdp-show -- --date YYYY-MM-DD --holes 18 --prefer latest-within-min-plus --max-over-min 15000 --step-ms 700
```

주요 모드:

- `cdp-start`: 실제 Chrome을 remote debugging 포트로 실행한다.
- `cdp-doctor`: CDP 연결과 탭 상태를 확인한다.
- `cdp-dry-run`: CDP Chrome에 연결해 빠르게 예약 페이지 신호를 확인한다.
- `cdp-show`: 보이는 Chrome에서 BOOKING 이동 → 날짜 선택 → 조건에 맞는 티타임 행 선택 → 행의 `예약` 버튼 클릭 → `03. 예약확인` 화면 표시까지 진행한다. 기본 `--prefer cheapest-latest`는 최저가 후보 중 가장 늦은 시간을 고른다. `--prefer latest-within-min-plus --max-over-min 15000`는 당일 최저가 대비 15,000원 이내 후보 중 가장 늦은 시간을 고른다.

`cdp-show` 안전선:

1. 시간표 행의 `예약` 버튼은 `03. 예약확인`을 표시하기 위한 선택 단계이므로 클릭할 수 있다.
2. `03. 예약확인` 아래의 최종 `예약하기` 버튼은 실제 확정 단계이므로 클릭하지 않는다.
3. `03. 예약확인` 화면은 개인정보가 포함될 수 있으므로 스크린샷/HTML 저장을 하지 않는다.
4. 콘솔/메시지 요약에서 성명/연락처는 `[redacted]`로 마스킹한다.
5. Slack/Telegram에 보낼 `approval.messageKo`를 생성하고, 마지막에 반드시 묻는다: “이 내역으로 예약을 확정할까요?”
6. 사용자가 명시적으로 `예약 확정`이라고 답한 뒤에만 최종 `예약하기`를 수행한다.
7. 사용자가 “예약하지마”, “하지마”, “나중에 다시 지시할게”라고 하면 현재 `03. 예약확인` 상태를 유지하더라도 최종 `예약하기`를 누르지 말고 즉시 중단한다.

### Date Change Optimization

예약 날짜를 바꿀 때는 홈 화면이나 `BOOKING` 메뉴부터 다시 들어가지 않는다. 현재 `booking01.asp` 예약 화면에 `Date_Click` 함수가 살아 있으면 그 자리에서 날짜만 바꾼다.

빠른 날짜 변경 절차:

1. 현재 페이지에서 `typeof Date_Click === 'function'`인지 확인한다.
2. 가능하면 바로 `Date_Click('YYYY','MM','DD')`를 실행한다.
3. 현재가 `03. 예약확인` 화면이라도 예약 페이지 함수가 살아 있으면 그대로 날짜만 바꾼다.
4. 함수가 없을 때만 브라우저 back 1회 또는 `booking01.asp` 직접 이동을 fallback으로 쓴다.
5. 절대 매번 홈 → 팝업 정리 → BOOKING 전체 플로우를 반복하지 않는다.
6. 사용자가 승인 대기 중 날짜를 바꾸면, 이전 날짜의 pending approval은 즉시 폐기한다. “N일 건은 확정하지 않고 중단”을 먼저 명시한 뒤 새 날짜로 다시 `03. 예약확인`까지 진행한다.

## Common Pitfalls

1. **텍스트 보고로 끝내기.** 이 데모는 관객이 보는 브라우저 조작이 핵심이다. 가능하면 실제 보이는 브라우저 상태를 확인하고 진행한다.
2. **4배속 기준을 유지하기.** 대표님은 4배속도 느리다고 피드백했다. 더나인GC 시연은 8배속 이상 실전 속도를 기본으로 한다.
3. **팝업을 남긴 채 예약 메뉴를 찾기.** 공지 팝업이 주요 메뉴를 가리거나 시선을 분산시킬 수 있으므로 먼저 빠르게 닫는다. 2026-06-09 기준 5개 팝업이 뜨는 흐름이 반복 확인됐다.
4. **팝업 제목 목록을 고정 사실처럼 다루기.** 팝업 제목은 운영/시즌 공지에 따라 달라질 수 있다. 현재 보이는 팝업을 기준으로 닫되, 절차는 `× CLOSE` 또는 `오늘 하루 동안 보이지 않기`로 동일하게 처리한다.
5. **팝업 본문을 닫기 버튼으로 착각하기.** 팝업 이미지/본문은 공지 상세 링크다. 오클릭하면 공지사항 상세 페이지로 이동한다. 반드시 `× CLOSE` 또는 `오늘 하루 동안 보이지 않기`를 누른다.
6. **Naver 예약 카드의 조건을 그대로 믿기.** Naver 장소 카드에는 티스캐너 제공 예약이 보일 수 있지만 `4인 필수`, `9홀X2회` 같은 조건이 붙을 수 있다. 3명 시나리오와 맞지 않으면 공식 사이트/로그인 후 조건을 재확인한다.
7. **로그인 필요를 예약 불가로 오해하기.** 로그인 전에는 재고/티타임이 숨겨질 수 있다. “예약 불가”가 아니라 “로그인 후 확인 필요”라고 말한다.
8. **예약 여부 질문에 장황하게 설명하기.** “예약했어?”에는 먼저 “아니요, 예약하지 않았습니다”처럼 상태를 짧게 답한다.
9. **최종 버튼을 시연 속도로 눌러버리기.** 빠른 조작은 검색/탐색 구간만 해당한다. 예약하기/예약 확정/결제/제출 앞에서는 반드시 멈추고 Final Confirmation Protocol을 수행한다.
10. **예약현황 없이 승인만 묻기.** “눌러도 될까요?”만 묻지 말고, 날짜/시간/인원/요금/주의사항 등 현재 예약현황을 먼저 보여준 뒤 승인 질문을 한다.
11. **모니터에 Chrome이 보인다고 가정하기.** Chrome 프로세스가 떠 있어도 실제 시연 화면에는 안 보일 수 있다. 듀얼 모니터의 음수 좌표, 최소화, Telegram/Slack 포커스 탈취, 작업표시줄 오클릭을 확인하고, 실제 화면 캡처로 Chrome 가시성을 검증한 뒤 진행한다.
12. **애쓰는 과정이 안 보이는 상태로 계속 시도하기.** 내부적으로 도구를 많이 써도 대표님 화면에서 검색창 선택, URL 입력, 클릭, 이동 같은 행동이 보이지 않으면 시연 실패다. 막히면 보이지 않는 시도를 반복하지 말고 Chrome 창을 watched monitor로 옮긴 뒤 한 동작씩 눈에 보이게 진행한다.
13. **사용자가 stop/멈춤을 말했는데 계속 조작하기.** 사용자가 “stop”, “멈춰 있어”, “안 보여”, “예약하지마”, “나중에 다시 지시할게”라고 하면 즉시 클릭/입력을 멈추고 현재 보이는 화면 상태만 보고한다.
14. **날짜 변경 때 전체 플로우를 다시 타기.** 이미 예약 화면에 있고 `Date_Click` 함수가 살아 있으면 날짜만 바꾸면 된다. 홈 → 팝업 → BOOKING을 반복하면 느리고 대표님이 답답해한다.
15. **진행 중 설명이 실행 속도를 늦추기.** 대표님은 실행 중 장황한 설명보다 빠른 처리를 원할 수 있다. 안전 경계와 최종 승인 질문 외에는 설명을 최소화한다.
